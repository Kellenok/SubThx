# subplz vs subthx: sync stage timings (2026-10-14)

Input: `[01] 探偵はもう、死んでいる。 [B0DQCZ9TNQ].m4b` (7.51 h, 27,027 s) with its epub.
Machine: RTX 4070 (12 GB), CUDA. Three runs per system, each a fresh process (cold model load).
Both systems read the same files from a warm OS file cache (the SubPlz runs came first).

## Stages, model load up to VAD (seconds, median of 3)

| Stage | subplz: whisper tiny (stable-ts + faster-whisper) | subthx: kitsune-p0.05b (ONNX, CUDA) |
|---|---|---|
| model load | 0.96 (runs 10.96, 0.78, 0.96) | 0.40 (runs 0.86, 0.40, 0.39) |
| audio decode | 18.9 (sum of 4 ffmpeg chunks, overlaps ASR) | 2.30 (sequential, before VAD) |
| VAD | 4.3 (Silero, batched, ONNX) | 1.63 (FireRedVAD, ONNX) |

## Beyond VAD (context)

| | subplz | subthx |
|---|---|---|
| ASR | 40.9 (pipeline 45.2 minus VAD 4.3) | 3.02 (runs 3.24, 3.02, 3.00) |
| total wall time | 47.7 (includes book alignment) | 8.07 (server job, median of the split runs below) |

## Alignment (after VAD)

| | subplz (batched, modified) | subthx |
|---|---|---|
| chapter matching | 0.08 s | not timed separately |
| alignment | 0.40 s (wall, the chapter pool) / 1.39 s CPU | 0.43 s (`align+write` in the job log, includes writing the file) |

The subplz alignment numbers are from the three reruns with the alignment timers (`tools/bench_stages_subplz.py`).

## Notes and caveats

- SubPlz decode runs in a background thread while the GPU transcribes, so its 18.9 s is work, not added wall time. subthx decodes before VAD, so its 2.3 s is wall time.
- subplz's first run loaded the model in 11 s: the OS file cache was cold for that file. The other two runs were warm. The median (0.96 s) is reported.
- subplz ASR is inferred as pipeline minus VAD: stable-ts calls transcribe through its own path, so transcribe itself could not be timed.
- Models differ: whisper tiny (39M) against Kitsune 0.05B (52M, fp16 on GPU). Accuracy is not part of this measurement.
- Earlier SubPlz benchmark numbers for the same book (`docs/benchmarks/archive/gemini-scratch`, see `subplz-state/BENCHMARK_AND_RUST_PLAN.md`) gave Whisper Tiny batched ASR 56.5 s on the same card. This run gave 40.9 s, so this run's numbers are the ones to compare with subthx.

## Accuracy (measured now, from the subtitle files each run wrote)

Same book metrics as the earlier table (`tools/eval_srt.py`: story chapters 1–11 of the audiobook, text of book chapters 2–12, NFKC and punctuation stripped). Two runs of each system, the same files:

| run | cues | book match | extra text | final CER |
|---|---|---|---|---|
| SubThx, Kitsune 0.05B, CUDA | 7,937 | 99.80% | 1,366 (1.25%) | 1.46% |
| SubPlz, batched path (modified), whisper tiny | 5,105 | 99.31% | 2,604 (2.36%) | 3.09% |

Both systems are scored on the same subtitle files they wrote. The earlier table scores SubPlz's own alignment of raw transcripts with `tools/eval_book.py`, which gives 99.45% / 2.37% / 2.96% for the batched SubPlz (the same cue count, 5,105): close to the numbers here. Its Kitsune row (99.78% / 0.88% / 1.11%) came from a different raw transcript than the one in `fixtures/e2e`; running `eval_book.py` on that fixture gives 99.83% / 1.24% / 1.42%.

## Original SubPlz (no batching), from the earlier benchmark table

The upstream tag v4.0.0 has no batched Whisper pipeline: it transcribes one chapter at a time. Re-running it takes about ten minutes, so its numbers are taken from the earlier full-book benchmark (`Whisper Tiny Base`, batch 1, 7.51 h, RTX 4070; see `archive/gemini-scratch/BENCHMARK_AND_RUST_PLAN.md`) and were not measured again for this document:

| | ASR | total | cues | book match | extra text | final CER |
|---|---|---|---|---|---|---|
| SubPlz, no batching (v4.0.0), batch 1 | 546.0 s | 654.1 s | 6,414 | 98.81% | 3.42% | 4.61% |
| SubPlz, batched 4-chunk path (modified, this document), batch 32 | 40.9 s | 47.7 s | 5,105 | 99.31% | 2.36% | 3.09% |
| SubPlz, batched, earlier table (`Whisper Tiny Batched`) | 56.5 s | 58.8 s | 5,105 | 99.45% | 2.37% | 2.96% |

The earlier table reports the ASR as its own column and the total as everything after the decode. Load and VAD are not in that table, so this document's stage split does not apply to the batch-1 row. The accuracy of the batched path is measured above, from its written subtitles.

## SubPlz model load and writing, measured separately

`tools/bench_load_write_subplz.py` runs the upstream v4.0.0 functions on their own: `get_model` (stable-ts + faster-whisper, whisper tiny, CUDA) in three cold processes, and `write_srt` on the 5,121 cues of a batched run, median of five writes.

```
load (clock starts before the imports): 2.311 s, 2.272 s, 2.241 s   (median 2.27 s)
write (Writer.write_sub): 0.0100 s for 5,121 cues    (SubThx: 0.01 s for 7,953 cues)
```

Model sizes on disk: Whisper tiny `model.bin` 75.5 MB (the Systran faster-whisper-tiny conversion); SubThx Kitsune 0.05B on CUDA `model.mixed16b.onnx` 104.6 MB plus the fp16 VAD 1.2 MB and the mel filterbank.
